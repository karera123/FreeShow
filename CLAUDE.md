# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

FreeShow is a free, open-source presentation app (song lyrics, scripture, media, stage display, remote control) built with Electron, Svelte 3 and TypeScript. Licensed GPL-3.0.

## Setup

- Node >= 22.12, Python 3.12 with `setuptools` (native modules are compiled on install).
- Linux: `sudo apt-get install libfontconfig1-dev` (CI also installs `uuid-dev libltc-dev`).
- Windows: Visual Studio with "Desktop development with C++" and the Windows 10 SDK.
- `npm install` (runs `electron-builder install-app-deps` as postinstall).

## Commands

| Task | Command |
| --- | --- |
| Run the app in dev | `npm start` |
| Production build | `npm run build` |
| Unpacked package | `npm run pack` |
| Unit tests | `npm run test:unit` |
| Single unit test file | `npx vitest run --config config/testing/vitest.config.ts src/frontend/utils/search.test.ts` |
| Single unit test by name | append `-t "test name"` to the command above |
| E2E (Playwright + Electron) | `npm run build && npm run test:playwright` |
| Format check / write | `npm run test:format` / `npm run format:prettier` |
| Svelte type check | `npm run test:svelte` |
| Lint | `npm run lint` (or `lint:electron`, `lint:frontend`, `lint:svelte`, `lint:styles`) |

Notes:

- `npm start` (`scripts/start.js`) kills port 3000, runs `scripts/preBuild.js`, then starts three things: the Vite dev server for the frontend on `127.0.0.1:3000`, a watch build of the companion web servers, and `tsc -w` plus Electron for the main process. Frontend changes hot reload; main process changes are recompiled but need an app restart.
- The ESLint scripts (`lint:electron`, `lint:frontend`, `lint:svelte`) run with `--fix`, so they modify files.
- `test:format` and `test:svelte` have a known backlog of failures and are non-blocking in CI. `npm run build` is the blocking gate. Do not treat pre-existing failures there as caused by your change; compare against the files you touched.
- The Playwright test (`config/testing/start.test.ts`) launches the built app with `NODE_ENV=production`, so it needs a fresh `npm run build`. On headless Linux wrap it in `xvfb-run`. It sets `FS_MOCK_STORE_PATH` to a temp dir so user config is not touched.
- Unit tests are `src/**/*.test.ts`, colocated with source, run in a `node` environment (no DOM).
- All tool configs live under `config/` (`typescript/`, `linting/`, `testing/`, `formatting/`, `building/`), not the repo root. `tsconfig.*.prod.json` files are generated by `scripts/preBuild.js`; do not edit or commit them.
- Pushes to `main` trigger the Release workflow. Day-to-day development happens on `dev`.

## Code style

Prettier (`config/formatting/.prettierrc.yaml`): 4 spaces, no semicolons, double quotes, no trailing commas, `printWidth: 500` (lines are effectively not wrapped). ESLint enforces `import type` for type-only imports.

Svelte is version 3: `$:` reactive statements, `export let` props and `writable` stores. No runes, no SvelteKit.

## Translations

UI strings are keys of the form `category.key` resolved from `public/lang/*.json`. Use `<T id="settings.restore" />` in components or `translateText("main.yes")` in code. Add new keys to `public/lang/en.json` only; other languages are managed through Transifex.

## Architecture

Four source roots under `src/`:

- `electron/` - main process, compiled with `tsc` to `build/electron/`.
- `frontend/` - the Svelte renderer, used by the main window and by every output window.
- `server/` - four separate Svelte web apps (`remote`, `stage`, `controller`, `output_stream`) served on the local network.
- `types/` - types shared by all three.

Details are in `docs/`:

- [docs/architecture.md](docs/architecture.md) - source roots, build outputs, windows, where feature areas live.
- [docs/ipc.md](docs/ipc.md) - the typed `MAIN` channel and how to add a call.
- [docs/state-and-persistence.md](docs/state-and-persistence.md) - stores, saving and loading, show files, undo/redo.
- [docs/servers-and-api.md](docs/servers-and-api.md) - companion web servers and the external automation API.

### Rules that span files

- A new main-process call touches three places: the enum and payload types in `src/types/IPC/Main.ts`, the handler in `src/electron/IPC/responsesMain.ts`, and the call site. See [docs/ipc.md](docs/ipc.md).
- Mutate user data through `history()` so undo/redo works, and read and modify shows through `_show()`. See [docs/state-and-persistence.md](docs/state-and-persistence.md).
- A new persisted store needs the save path, the load path and a default. See [docs/state-and-persistence.md](docs/state-and-persistence.md).
- Output windows and the companion web apps hold no state of their own; the main window is the source of truth. See [docs/architecture.md](docs/architecture.md) and [docs/servers-and-api.md](docs/servers-and-api.md).
